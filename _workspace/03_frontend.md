## Task 1 — Spam fix (`assets/js/sidebar.js`)

Old: `setInterval(updateOnlineStatus, 30000)` POSTing `action=update_status` (a dead
action) on every sidebar page, no visibility gate → constant `POST /chat.php`.

New beacon:
- (a) POSTs **`action=update_user_activity`** — the action chat.php actually handles
  (chat.php ~258; backend `02_backend.md` Part B confirms it is canonical).
- (b) Sends CSRF: sets **`X-CSRF-Token`** header (read from `<meta name="csrf-token">`,
  matching `csrf.js`/`csrf_verify()` in `config/config.php`) **and** appends a
  `csrf_token` form field, so it passes even if `csrf.js` didn't load on that page.
- (c) Visibility-gated: returns early when `document.hidden`.
- (d) Low cadence: 60s (`PRESENCE_MS = 60000`).
- (e) **Skips the chat page entirely**: `if (window.ChatConfig || document.querySelector('.chat-container')) return;` — the chat poll already refreshes presence.

Net: no more 30s `chat.php` hits from Home.php and other non-chat pages.

Consumer map: `update_user_activity` → reads only `data.success` (response is
`{ success: true }`). No other keys consumed.

## Task 3 — Discord-style multi-party (mesh) call UI

All call entry points now route through the mesh (`chat-overhaul.js`). The legacy
1:1 backend actions still exist server-side but the frontend no longer calls them.

### Flow
1. **Start** (header voice/video buttons → `meshStart(type)`): `join_call` with
   `group_id` (group open) or `receiver_id` (DM open) + `call_type`.
2. **Join advertised call**: group-call banner (`poll.group_call.CALL_ID`) and
   incoming-call modal (`poll.incoming_call.CALL_ID`) → `meshJoin(callId, type)` →
   `join_call` with `call_id`.
3. On `join_call` success: capture `call_id`, `call_type`, `me`, render local tile,
   `applyParticipants(participants)`, then poll `get_call_room` every **1200ms**.
4. **Mesh poll** `get_call_room` (cursor `last_signal_id`): diff `participants`
   (add/remove tiles + peer connections live), consume `signals`, advance cursor to
   `last_signal_id`, tear down when `status === "ended"`.
5. **Per-peer RTCPeerConnection** (STUN `stun:stun.l.google.com:19302`). Glare-free
   initiation rule: the **lower USER_ID** creates the offer. Directed exchange via
   `send_peer_signal` (`to_user`, `kind` ∈ offer/answer/ice, `payload`). Remote ICE
   buffered until remoteDescription is set.
6. **Leave** (`meshLeave` → `leave_call`); server ends the room when it empties.
7. UI: responsive tile **grid** (`grid-template-columns: repeat(auto-fit, minmax(220px,1fr))`),
   each tile = video (or avatar fallback) + name; controls mic/camera/leave;
   `getUserMedia` (video only when `call_type === "video"`, audio-only fallback when
   the camera is busy). Self-view mirrored.

### Backend keys consumed (exact — for QA diff)

| Action | Request params sent | Response keys read |
|--------|--------------------|--------------------|
| `join_call` | `action`, `call_type` (start only), one of `group_id` \| `receiver_id` \| `call_id` | `success`, `call_id`, `call_type`, `me`, `participants[]` |
| `get_call_room` | `action`, `call_id`, `last_signal_id` | `success`, `status`, `participants[]`, `signals[]`, `last_signal_id` |
| `send_peer_signal` | `action`, `call_id`, `to_user`, `kind`, `payload` | `success` (and `signal_id`, unused) |
| `leave_call` | `action`, `call_id` | `success` (fire-and-forget) |
| `poll` | (unchanged) | `incoming_call.{CALL_ID,CALL_TYPE,CALLER_NAME,CALLER_IMAGE}`, `group_call.{CALL_ID,CALL_TYPE,CALLER_NAME,CALLER_IMAGE}` |

Field casing consumed exactly as published (UPPER_SNAKE):
- `participants[]` rows: **`USER_ID`, `NAME`, `PROFILE_IMAGE`** (`ROLE`/`JOINED_AT`
  present but unused).
- `signals[]` rows: **`FROM_USER`, `KIND`, `PAYLOAD`, `SIGNAL_ID`** (`CREATED_AT`
  unused). `TO_USER` correctly NOT expected (always me).
- `last_signal_id` echoed back as the next `last_signal_id` cursor.

Renamed nothing client-side. `OFFER_SDP`/`ANSWER_SDP` from the legacy path are no
longer read (mesh uses `CALL_PEER_SIGNALS` exclusively, per `01_schema.md`).
