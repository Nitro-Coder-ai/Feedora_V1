## Diff 3 — Presence spam fix  [OK]

`assets/js/sidebar.js` rewritten, verified against `config/config.php` `csrf_verify()`:
- (a) Posts `action=update_user_activity` — a real handled branch (chat.php 258). The
  dead `update_status` string now survives only in the header comment (1 hit, not code);
  build confirms `sidebar.min.js` contains `update_user_activity`. [OK]
- (b) CSRF: sends BOTH `X-CSRF-Token` header AND `csrf_token` form field.
  `csrf_verify()` accepts `$_SERVER['HTTP_X_CSRF_TOKEN'] ?? $_POST['csrf_token']`
  (config.php 150) — either form passes; sidebar sends both, so it passes even if
  `csrf.js` never loaded on that page. Token source `<meta name="csrf-token">` is
  emitted on sidebar pages (verified `Home.php` line 14). [OK]
- (c) Visibility-gated: `if (document.hidden) return;`. [OK]
- (d) Low cadence: `PRESENCE_MS = 60000` (60s, down from 30s). [OK]
- (e) Bails on chat page: `if (window.ChatConfig || document.querySelector('.chat-container')) return;`. [OK]

Net effect confirmed: from Home.php (and any non-chat sidebar page) the beacon now fires
`update_user_activity` at 60s, only while visible — and never on chat.php. The old
30s `update_status` flood from non-chat pages is gone. [OK]

## Diff 4 — Security  [OK]

- `csrf_verify()` runs once at top of chat.php (line 12), before the action dispatch, so
  it covers ALL new mesh actions + `update_status` alias. State-changing POST without a
  valid token → 403 JSON before any DB write. [OK]
- Membership/participant guards present on BOTH ends:
  - `join_call`: group path → `isGroupMember`; existing-room path → group member OR
    CALLER_ID/RECEIVER_ID of the room (chat.php 911-913). [OK]
  - `get_call_room`: `isActiveParticipant(callId, me)` (968). [OK]
  - `send_peer_signal`: `isActiveParticipant(callId, me)` AND
    `isActiveParticipant(callId, to_user)` (997-1002) — both ends. [OK]
  - `leave_call`: repo scopes UPDATE by `(call_id, me)` — can only flip own row. [OK]
- Prepared statements only — all DB access via `CallRepository` (bound params, no
  interpolation) + the existing prepared `update_status` upsert. No user input in SQL. [OK]
- Whitelists: `putSignal` rejects KIND ∉ {offer,answer,ice} (returns 0 → "Invalid
  signal"); `createRoom` clamps call_type to voice|video. Frontend never has to be
  trusted for these. [OK]

## WARN (non-blocking)

- **[WARN] CLAUDE.md ↔ Playwright contradiction (for the leader).** `CLAUDE.md`
  "No Third-Party Test Tooling" prohibits Playwright/Puppeteer/Cypress/Selenium and
  declares the Chrome Extension MCP the single source of validation. But the repo
  **ships and uses Playwright**: `tests/` (auth.setup.ts, dashboard.spec.ts,
  post.spec.ts, comment.spec.ts, pages/…) and `package.json` (`"test": "playwright
  test"`, `@playwright/test ^1.49.0`). The harness note in CLAUDE.md acknowledges this.
  Per instruction I did NOT run Playwright. Leader must decide: delete the ban from
  CLAUDE.md, or retire the suite. They cannot both stand.

- **[WARN] No live visual/browser pass.** Per CLAUDE.md I did not drive a browser, so
  the 3-column dense redesign and the multi-party tile grid were verified by code/markup
  + build only — NOT visually at 100% zoom or across the responsive breakpoints
  (≤1199 info overlay, ≤767 drawer). The frontend contract states the same caveat.
  Recommend a manual or Chrome-MCP layout pass before declaring task 2/3 "done".

- **[WARN] Mesh room STATUS never flips to `active`.** `createRoom` leaves
  CALL_SESSIONS.STATUS='ringing' and no action promotes it to 'active'. The mesh works
  (frontend only tears down on `status==='ended'`), but the live-call advertisement
  windows are time-boxed: `poll.incoming_call` (RECEIVER_ID=me, STATUS='ringing', <60s)
  and `poll.group_call` (STATUS IN ringing/active, <120s). A late joiner discovering a
  call older than 120s via the banner won't see it (they can still join with an explicit
  call_id). Not a contract mismatch and not a blocker — flagging as a known limitation
  if longer-running call discovery is expected. Also: the poll's incoming/group_call
  queries still SELECT the legacy `OFFER_SDP`, which the mesh frontend no longer reads
  (harmless dead field).
